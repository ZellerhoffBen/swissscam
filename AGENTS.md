# Coding guidelines

This is a small Python hackathon project built by three apprentices. Keep code easy for everyone to understand.

- Follow KISS and YAGNI. Implement only what was requested.
- Prefer short, readable code over clever or overly compact code.
- Use clear names, small functions and straightforward control flow.
- Use type hints for function inputs and outputs.
- Add brief comments explaining intent, assumptions or mock behaviour. Do not narrate obvious code.
- Prefer the standard library and existing dependencies. Add packages only when needed.
- Avoid unnecessary classes, abstractions, configuration and extra files.
- Keep frontend, transcription and detection separate; keep their interfaces simple.
- Mark mocks clearly. Never present mock output as real analysis.
- Make focused changes, preserve unrelated work and check the affected flow.
- Keep documentation and explanations concise. Write code and comments in English.
